# Система керування комп'ютерним класом (Python)

Невеликий прототип для керування навчальним класом у межах авторизованої
шкільної локальної мережі. Складається з програми вчителя (`teacher.py`) та
агента учня (`student_agent.py`), які працюють на Windows і Linux.

> [!IMPORTANT]
> Перед використанням обов'язково прочитайте [IMPORTANT.md](IMPORTANT.md) —
> критичні застереження, відомі проблеми та способи їх усунення, а також
> відмову авторів від гарантій і відповідальності.

Можливості:

- перегляд екранів підключених учнів у вигляді мініатюр (сітка 3×5 з
  прокруткою, автоматично розширюється);
- окремий збільшений перегляд екрана учня;
- демонстрація екрана вчителя вибраним учням;
- надсилання текстових повідомлень;
- передавання файлів учням (журнал передач);
- перегляд відеофайлу на комп'ютерах учнів (відтворення штатним плеєром,
  автоматичне видалення після перегляду);
- перегляд відео з YouTube — відкриття посилання у браузері учня;
- блокування комп'ютерів учнів (перекриття екрана + блокування введення);
- блокування лише введення (миша й клавіатура) **без** перекриття екрана;
- блокування виходу в інтернет (локальна мережа лишається доступною);
- вимкнення комп'ютерів учнів із відліком.

## Вимоги

- Python 3.10 або новіший на кожному комп'ютері.
- Учитель: `Pillow`.
- Агенти учнів: `mss` і `Pillow`.
- Усі комп'ютери мають бути в одній доступній локальній мережі.
- Використовуйте лише з дозволу школи й після повідомлення учнів.
  Агент працює видимо в терміналі та зупиняється через Ctrl+C.

Підтримуються Windows і Linux. Блокування введення спирається на можливості
операційної системи (X11-захоплення / хуки керування), тому на деяких
конфігураціях воно може бути недоступним — у такому разі агент чесно
повідомляє про це вчителю.

## Встановлення залежностей

### Комп'ютер учителя
```bash
python -m pip install Pillow
```

### Кожен комп'ютер учня
```bash
python -m pip install mss Pillow
```

Для показу демонстрації екрана вчителя та блокування комп'ютера агентові
потрібен **tkinter** (окремий системний пакет, через `pip` не ставиться). На
Debian/Ubuntu/antiX та подібних:
```bash
sudo apt install python3-tk
```
Для показу зображень демонстрації також потрібна підтримка Tk у Pillow
(пакет `python3-pil.imagetk`):
```bash
sudo apt install python3-pil.imagetk
```
Без tkinter агент усе одно передає екран учня, але не зможе відображати
демонстрацію вчителя й не підтримуватиме блокування (про це він попередить у
терміналі).

На Linux, якщо `pip` відмовляється встановлювати у систему, скористайтеся
віртуальним середовищем:
```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install mss Pillow
```
Пакети `python3-tk` і `python3-pil.imagetk` мають бути встановлені для тієї ж
версії Python, яку використовує віртуальне середовище.

На частині стільниць Linux захоплення екрана потребує сесії X11. Під Wayland
дозволи на захоплення екрана залежать від стільниці й можуть блокувати його.
Перевірте це на цільових машинах.

> Встановлення цих залежностей можна виконати автоматично за допомогою
> майстра `skkk_setup.py` (учитель) або `skkk_student_setup.py` (учень).

## Майстер налаштування середовища (`skkk_setup.py`)

`skkk_setup.py` — графічний помічник, який готує комп'ютер учителя до роботи.
Його можна запустити окремо або він запускається автоматично з `teacher.py`,
якщо середовище ще не налаштоване:

```bash
python skkk_setup.py
```

Майстер послідовно перевіряє й за потреби налаштовує:

| Крок | Що перевіряється / робиться |
|------|------------------------------|
| Версія Python | потрібна 3.10 або новіша |
| `tkinter` | графічна бібліотека (apt: `python3-tk`) |
| `Pillow` (PIL) | обробка зображень (apt/pip: `python3-pil` / `Pillow`) |
| `ImageTk` | показ зображень у Tk (apt: `python3-pil.imagetk`) |
| `mss` | захоплення екрана (apt/pip: `python3-mss` / `mss`) |
| Локальна мережа | наявність активного IPv4-інтерфейсу та широкомовлення |
| TCP 8765 / UDP 8766 | чи вільні потрібні порти |
| Фаєрвол | відкриття вхідних портів (`ufw`, `firewalld`, `iptables`, Windows Firewall) |
| Синхронізація часу | увімкнення NTP (`chrony`/`systemd`/…) або `w32time` |
| Токен доступу | створення `classroom_token.txt`, якщо його немає |
| Файл налаштувань | створення `classroom_config.json` за потреби |

Відсутні компоненти встановлюються автоматично (`apt-get` на Linux, `pip` за
потреби). Для дій, що потребують прав `root`, з'являється вікно із запитом
пароля (на Windows — запит UAC); майстер пояснює, навіщо потрібні права.

Результати показуються у **журналі дій**: успішні кроки позначаються зеленою
галочкою `✔`, невдалі — червоним `✘`, попередження — знаком `!`. Після
завершення майстер повідомляє про успішне налаштування і пропонує одразу
запустити `teacher.py`.

Успішне завершення фіксується у файлі
`~/.config/classroom_screen_monitor/setup.json`, завдяки чому `teacher.py` не
запускає майстер повторно.

## Пакування у виконувані файли (PyInstaller)

Обидві сторони можна зібрати в самодостатні застосунки (режим **One Dir**),
щоб не встановлювати Python і бібліотеки на кожному комп'ютері:

- сторону **вчителя** (`teacher.py`, `skkk_setup.py`) — у теку `dist/`;
- сторону **учня** (`student_agent.py`, `skkk_student_setup.py`, `netguard.py`)
  — в окрему теку `dist/student/`.

Спочатку встановіть PyInstaller:

```bash
pip install pyinstaller
```

### Сторона вчителя — тека `dist/`

```bash
./build_exe.sh        # Linux
build_exe.bat         # Windows
```

Обидва застосунки складаються в **одну теку** `dist/` зі **спільною** текою
бібліотек `shared_libs/`:

| Файл | Призначення |
|------|-------------|
| `dist/teacher` (`teacher.exe`) | програма вчителя |
| `dist/skkk_setup` (`skkk_setup.exe`) | майстер налаштування середовища |
| `dist/shared_libs/` | СПІЛЬНІ бібліотеки та залежності обох застосунків (одна копія; іконки `img/` та `icon.png` також усередині) |

**Важливо:** розповсюджуйте/копіюйте **всю теку `dist/` цілком** —
`teacher` запускає майстер як сусідній файл (`skkk_setup` поряд), а спільні
файли даних лежать у тій самій теці.

Шляхи до зовнішніх файлів враховують збірку:

- `classroom_token.txt` і `classroom_config.json` читаються й створюються
  **поряд із виконуваними файлами** (у теці `dist/`, а не всередині бандла);
- за потреби шлях можна перевизначити змінними середовища
  `CLASSROOM_TOKEN_FILE` та `CLASSROOM_CONFIG`;
- стан налаштування (`~/.config/classroom_screen_monitor/…`) зберігається як і
  раніше;
- бібліотеки (`Pillow`, `ImageTk`, `mss`) вбудовуються у застосунок, тож
  майстер у зібраному вигляді не намагається їх встановлювати (`mss`
  додається через `--hidden-import mss`, бо імпортується ліниво);
- для `ImageTk` додаються `--hidden-import PIL.PngImagePlugin PIL._imagingtk
  PIL._tkinter_finder` (без останнього іконки кнопок у зібраному застосунку
  не завантажуються);
- іконка застосунку `icon.png` вбудовується в бандл і встановлюється як
  іконка вікна; на Windows вона ж передається у `--icon` (іконка `.exe`).

### Сторона учня — тека `dist/student/`

```bash
./build_exe_student.sh   # Linux
build_exe_student.bat    # Windows
```

Збірка складає **три застосунки в окрему теку** `dist/student/`:

| Файл | Призначення |
|------|-------------|
| `dist/student/student_agent` (`student_agent.exe`) | агент учня (екран, файли, блокування) |
| `dist/student/skkk_student_setup` (`skkk_student_setup.exe`) | меню налаштування учнівського ПК |
| `dist/student/netguard` (`netguard.exe`) | привілейований клієнт керування мережею |
| `dist/student/shared_libs/` | СПІЛЬНІ бібліотеки та залежності всіх трьох застосунків (одна копія) |
| `dist/student/icon.png` | іконка застосунків |

**Важливо:** розповсюджуйте/копіюйте **всю теку `dist/student/` цілком** —
`student_agent` запускає налаштування як сусідній файл, а обидва застосунки
використовують сусідній зібраний `netguard`.

Особливості учнівської збірки:

- `classroom_token.txt` і `classroom_config.json` читаються/створюються
  **поряд із виконуваними файлами** (у теці `dist/student/`);
- майстер у зібраному вигляді не встановлює бібліотеки (вони вбудовані) і
  позначає бібліотеки як «вбудовано»;
- автозавантаження агента (`.desktop` / antiX `startup` / Windows Startup)
  вказує на зібраний `student_agent`, а не на `python student_agent.py`;
- автозавантаження netguard налаштовується **із самого майстра** (без окремих
  скриптів-обгорток): завдання `@reboot` у `crontab` root на Linux або
  заплановане завдання `ClassroomNetguard` на Windows;
- `icon.png` встановлюється як іконка вікон агента та майстра.


## Запуск програми вчителя

```bash
python teacher.py
```

Під час першого запуску програма перевіряє, чи середовище вже налаштоване. Якщо
токена доступу ще немає або налаштування не завершувалося, `teacher.py`
автоматично запускає графічний майстер **`skkk_setup.py`** (див. розділ нижче).
Майстер:

- створює випадковий **токен доступу** та зберігає його у файлі
  `classroom_token.txt` поряд із `teacher.py` (права доступу лише для
  власника) — скопіюйте цей файл на комп'ютери учнів;
- перевіряє наявність потрібних бібліотек (`tkinter`, `Pillow`, `ImageTk`,
  `mss`) і за потреби встановлює їх;
- вмикає **автоматичну синхронізацію часу** (NTP на Linux, служба `w32time` на
  Windows) — однаковий час на всіх комп'ютерах потрібен для надійного
  автовизначення вчителя;
- перевіряє, чи відкрито вхідний **TCP-порт 8765** (передавання зображень) та
  **UDP-порт 8766** (виявлення), і за потреби відкриває їх у локальному
  фаєрволі (Windows Firewall, `ufw`, `firewalld` або `iptables`);
- створює `classroom_config.json` (за потреби).

Перед будь-яким запитом прав адміністратора майстер **пояснює, навіщо вони
потрібні** (вікно «Права адміністратора» з полем для пароля), виконує дію від
`root` і показує результат. Сам `teacher.py` цих налаштувань уже не робить.

Дізнайтеся IP-адресу комп'ютера вчителя в локальній мережі:
- Windows: `ipconfig`
- Linux: `ip addr`

Не відкривайте цей порт у публічний інтернет; за можливості обмежте доступ
лише шкільною мережею.

### Ярлик запуску «Start Teacher»

У теці проєкту є готовий лаунчер для запуску програми вчителя без консолі:

| Файл                    | Дія                                                       |
|-------------------------|-----------------------------------------------------------|
| `start_teacher.sh`      | Linux: запуск `nohup python3 teacher.py > teacher.log`    |
| `stop_teacher.sh`       | Linux: зупинка `pkill -f teacher.py`                       |
| `start_teacher.desktop` | Linux (XFCE/GNOME/KDE): те саме через ярлик `.desktop`     |
| `start_teacher.bat`     | Windows: запуск `pythonw teacher.py` (без вікна консолі)   |

**Linux.** `.desktop` визначає теку проєкту через `%k`, тому файл має лежати
поряд із `teacher.py`. Щоб винести ярлик на робочий стіл, створіть на нього
символьне посилання:

```bash
ln -s "$(pwd)/start_teacher.desktop" ~/Desktop/
```

Журнал роботи — `teacher.log` у теці проєкту (створюється лише за потреби,
наприклад при помилці).

**antiX / MX-Fluxbox (ROX-Filer, IceWM, Fluxbox).** Файловий менеджер
**ROX-Filer не запускає `.desktop`** при подвійному кліку — саме тому ярлик
«нічого не робить». Використовуйте натомість виконувані shell-скрипти
`start_teacher.sh` / `stop_teacher.sh`: подвійний клік у ROX-Filer (або
«Виконати» з контекстного меню) чи запуск із термінала `./start_teacher.sh`.
Скрипти самі переходять у теку проєкту, тому їх можна викликати звідусіль і
розміщувати символічним посиланням на панелі/робочому столі.

**Windows.** Подвійний клік на `start_teacher.bat` запускає програму через
`pythonw` — без вікна консолі. Якщо `pythonw` відсутній у `PATH`, буде
використано звичайний `python` (тоді з'явиться вікно консолі). Програма
вчителя має графічний інтерфейс, тож консоль їй не потрібна.

## Меню налаштування учнівського комп'ютера (`skkk_student_setup.py`)

`skkk_student_setup.py` — графічне меню, яке готує комп'ютер учня до роботи.
Його можна запустити окремо або воно відкривається автоматично з
`student_agent.py`, якщо комп'ютер ще не налаштований:

```bash
python skkk_student_setup.py
```

Меню має шість кнопок:

| Кнопка | Що робить |
|--------|-----------|
| **Налаштування системи** | автоматичне налаштування: перевіряє/встановлює компоненти (див. таблицю нижче), перевіряє локальну мережу, вмикає синхронізацію часу, відкриває вхідний UDP-порт у фаєрволі, дозволяє вимкнення по мережі (sudoers), імпортує токен доступу та створює файл налаштувань |
| **Додати в Автозавантаження** | додає агента учня та привілейований netguard до автозавантаження |
| **Видалити з Автозавантаження** | прибирає агента учня та netguard з автозавантаження |
| **Запустити систему** | запускає netguard **з правами адміністратора** та агента учня, якщо вони ще не працюють |
| **Зупинити систему** | зупиняє netguard і агента учня (комп'ютер при цьому **не** вимикається) |
| **Перевірити параметри** | показує стан токена, налаштувань, мережі, синхронізації часу, фаєрвола, дозволу на вимкнення, автозавантаження та процесів |

Кнопка **«Налаштування системи»** перевіряє й за потреби налаштовує:

| Крок | Що перевіряється / робиться |
|------|------------------------------|
| Версія Python | потрібна 3.10 або новіша |
| `tkinter` | графічна бібліотека (потрібна для демонстрації та блокування) |
| `Pillow` (PIL) | обробка зображень (apt/pip: `python3-pil` / `Pillow`) |
| `ImageTk` | показ зображень у Tk (apt: `python3-pil.imagetk`) |
| `mss` | захоплення екрана (apt/pip: `python3-mss` / `mss`) |
| Локальна мережа | наявність активного IPv4-інтерфейсу та широкомовлення |
| Синхронізація часу | увімкнення NTP (`chrony`/`systemd`/…) або `w32time` |
| Фаєрвол | відкриття вхідного UDP-порту виявлення (щоб отримувати оголошення вчителя) |
| Вимкнення по мережі | створення файла `/etc/sudoers.d/classroom-poweroff`, щоб учень (не root) міг вимкнути комп'ютер за командою вчителя без пароля (`sudo -n poweroff`/`shutdown`) |
| Токен доступу | **імпорт** `classroom_token.txt`, скопійованого з комп'ютера вчителя |
| Файл налаштувань | створення `classroom_config.json` за потреби |

> **Токен тут не створюється.** Він має бути таким самим, як на комп'ютері
> вчителя, тому меню лише допомагає вибрати й скопіювати готовий файл
> `classroom_token.txt`. Докладніше — розділ «Запуск програми вчителя».

Відсутні бібліотеки встановлюються автоматично (`apt-get`/`pip`). Дії, що
потребують прав адміністратора (фаєрвол, синхронізація часу, дозвіл на
вимкнення по мережі, автозапуск і запуск netguard), супроводжуються вікном із
запитом пароля; меню пояснює, навіщо потрібні права.

**Автозавантаження** (кнопки «Додати…» / «Видалити…») налаштовує:

- *агент учня* — `~/.config/autostart/student_agent.desktop` (XDG-стільниці),
  `~/.desktop-session/startup` (antiX/IceWM/Fluxbox) або `.bat` у теці
  «Автозавантаження» Windows;
- *netguard* — завдання `@reboot` у `crontab` root (Linux) або заплановане
  завдання `ClassroomNetguard` з правами SYSTEM (Windows). Обидва варіанти
  потребують прав адміністратора й налаштовуються безпосередньо з меню.

Перебіг виконання та результати показуються у **журналі**: успішні рядки —
зелена галочка `✔`, невдалі — червоний `✘`, попередження — `!`. Успішне
завершення «Налаштування системи» фіксується у файлі
`~/.config/classroom_screen_monitor/student_setup.json`, тому агент не запускає
меню повторно.

## Запуск агента учня

Із теки, де лежить `student_agent.py`:

```bash
python student_agent.py
```

Якщо комп'ютер учня ще не налаштований, агент під час першого запуску
автоматично відкриває меню `skkk_student_setup.py` (див. розділ вище), щоб
перевірити бібліотеки, імпортувати токен і за потреби налаштувати
автозавантаження (окремими кнопками).
Керувати цим може `--token`/`--token-file` (пропускає меню) та `--no-viewer`
(без вікон).

Агент **сам знаходить** учителя: він і слухає UDP-оголошення вчителя, і
періодично надсилає підписаний запит «де вчитель?», на який учитель відповідає
напряму (це працює, навіть коли широкомовні пакети від учителя не доходять).
Якщо широкомовлення заблоковане мережею, агент додатково перебирає адреси
своєї підмережі, надсилаючи запит кожній напряму. Якщо автовизначення все одно
не працює, вкажіть IP-адресу вчителя першим аргументом:

```bash
python student_agent.py 192.168.1.10
```

Під час пошуку агент також намагається відкрити вхідний UDP-порт виявлення
(8766) у локальному фаєрволі, щоб отримувати оголошення та відповіді вчителя,
і вмикає **автоматичну синхронізацію часу** (NTP / `w32time`). І перед
відкриттям порту, і перед увімкненням синхронізації агент спершу **пояснює,
навіщо потрібні права адміністратора**, і лише потім показує системний запит
пароля.

Токен агент читає з файлу `classroom_token.txt` поряд із `student_agent.py`
(шлях можна змінити змінною середовища `CLASSROOM_TOKEN_FILE`).

Додаткові аргументи:

```bash
python student_agent.py --name "ПК-07" --interval 1.5 --save-dir "~/Файли"
```

| Аргумент            | Опис                                                              |
|---------------------|-------------------------------------------------------------------|
| `teacher_ip`        | IP учителя (необов'язково; без нього — автовизначення)            |
| `--port`            | TCP-порт (резервний; за замовчуванням 8765)                       |
| `--discovery-port`  | UDP-порт виявлення (за замовчуванням 8766)                        |
| `--token`           | спільний токен (необов'язково; інакше — з файлу)                  |
| `--token-file`      | шлях до файлу з токеном                                           |
| `--interval`        | секунд між кадрами екрана (за замовчуванням 1.0, мінімум 0.5)     |
| `--name`            | ім'я, яке бачить учитель (за замовчуванням — ім'я комп'ютера)     |
| `--save-dir`        | куди зберігати файли від учителя                                  |
| `--no-viewer`       | без вікон (демонстрація й повідомлення виводяться в термінал)     |

Зупинити передавання — Ctrl+C у терміналі учня. Агент автоматично
перепідключається після тимчасового обриву зв'язку.

За замовчуванням файли від учителя зберігаються в теці
`Завантаження/Файли від вчителя` (або `~/Файли від вчителя`).

### Фонові ярлики «Start Student» / «Stop Student»

У теці проєкту є готові лаунчери для запуску та зупинки агента у фоні:

| Файл                   | Дія                                                             |
|------------------------|-----------------------------------------------------------------|
| `start_student.sh`     | Linux: запуск `nohup python3 student_agent.py > student_a.log`  |
| `stop_student.sh`      | Linux: зупинка `pkill -f student_agent.py`                       |
| `start_student.desktop`| Linux (XFCE/GNOME/KDE): те саме через ярлик `.desktop`           |
| `stop_student.desktop` | Linux (XFCE/GNOME/KDE): зупинка через ярлик `.desktop`           |
| `start_student.bat`    | Windows: запуск агента у згорнутому вікні з журналом            |
| `stop_student.bat`     | Windows: зупинка агента (через PowerShell)                       |

**Linux.** `.desktop` файли визначають теку проєкту через `%k`, тому їх
**не можна переміщати** — мають лежати поряд із `student_agent.py`. Щоб
винести на робочий стіл, створіть на них **символьні посилання**:

```bash
ln -s "$(pwd)/start_student.desktop" ~/Desktop/
ln -s "$(pwd)/stop_student.desktop" ~/Desktop/
```

Якщо система не запускає `.desktop` з першого разу, позначте файли як
довірені (`gio set start_student.desktop metadata::trusted true`) або просто
клікніть «Довіряти й запускати». Журнал роботи — `student_a.log` у теці проєкту.

**antiX / MX-Fluxbox (ROX-Filer, IceWM, Fluxbox).** Файловий менеджер
**ROX-Filer не запускає `.desktop`** при подвійному кліку — ярлик «нічого не
робить», хоча `python3 student_agent.py` у терміналі працює. Використовуйте
виконувані shell-скрипти `start_student.sh` / `stop_student.sh`:

```bash
./start_student.sh      # запуск у фоні, журнал student_a.log
./stop_student.sh       # зупинка
```

Скрипти самі переходять у теку проєкту (працюють при виклику звідки завгодно),
тому їх можна кинути на робочий стіл/панель ROX-Filer чи IceWM. Якщо ROX-Filer
пропонує вибір — оберіть «Виконати» (Execute).

**Windows.** Запускайте `.bat` подвійним кліком; він сам переходить у свою
теку (`%~dp0`). Журнал — `student_a.log`. Щоб приховати вікно консолі повністю,
замініть у `start_student.bat` `python` на `pythonw` (але тоді журнал не
писатиметься).

## Керування класом (у програмі вчителя)

Учні позначаються прапорцями на картках. Кнопки згруповано у три блоки.

**Вибір:**
- **Усі** / **Зняти** — позначити або зняти позначення з усіх комп'ютерів.

**Керування виділеними комп'ютерами:**
- **Показати мій екран** — демонстрація екрана вчителя вибраним учням;
- **Повідомлення** — надіслати текстове повідомлення;
- **Надіслати файли** — передати файли учням;
- **Перегляд відеофайлу** — надіслати відео на комп'ютери учнів і одразу
  відтворити його штатним відеоплеєром (детальніше нижче);
- **Відео з YouTube** — відкрити посилання на відео у браузері учнів;
- **Блокувати** / **Розблокувати** — перекрити екран і заблокувати введення;
- **Блокувати введення** / **Розблокувати введення** — блокувати лише мишу
  й клавіатуру, не перекриваючи екран;
- **Вимкнути** — вимкнути комп'ютери з відліком;
- **Блокувати Інтернет** / **Розблокувати Інтернет** — локальна мережа
  лишається доступною.

**Інфо:**
- **Журнал передачі файлів** — стан і результат передач;
- **Журнал повідомлень** — історія надісланих текстових повідомлень;
- **Загальна інформація** — відомості про з'єднання.

Стан кожного комп'ютера показано бейджами на картці (блокування, введення,
живлення, інтернет).

### Збільшений перегляд екрана учня

**Клік у будь-якому місці картки** (заголовок, бейджі, мініатюра) відкриває
велике вікно з екраном цього учня. Зображення оновлюється наживо (кожні 0.5 с)
і автоматично масштабується під розмір вікна із збереженням пропорцій; у
заголовку видно ім'я учня, а на панелі — роздільність кадру та час останнього
оновлення. Повторний клік по тій самій картці не відкриває друге вікно, а
підносить уже наявне.

Кнопка **Зберегти знімок…** зберігає поточний кадр у PNG або JPEG у рідній
роздільності учня. **Закрити** або клавіша **Esc** закриває вікно. Якщо учень
від'єднується, вікно показує повідомлення «Зв'язок із учнем втрачено…» (і
відновлюється, щойно комп'ютер знову під'єднається). Чекбокс вибору на картці
клік не перехоплює — він, як і раніше, лише позначає учня.

### Передавання файлів

Вікно **Журнал передачі файлів** (відкривається автоматично після надсилання)
показує для кожної передачі **смугу поступу з відсотками** та стан
(у черзі / передається / очікує підтвердження / збережено / відтворено).

Кожну активну передачу (або перегляд відео) можна **примусово зупинити**
кнопкою **✕ Зупинити**. Зупинена передача **не поновлюється**: учень отримує
сповіщення про скасування, а в журналі учителя з'являється стан «Скасовано
вчителем». Так само, якщо передачу перерве учень (помилка запису, обрив
зв'язку тощо), учитель бачить причину, а передача не відновлюється.

## Перегляд відео

### Відеофайл

Кнопка **Перегляд відеофайлу** відкриває вікно вибору адресатів. Виберіть
відеофайл — його буде:

1. передано на комп'ютери учнів у **тимчасову папку**;
2. відтворено **штатним відеоплеєром** системи (Linux та Windows);
3. **видалено** на комп'ютері учня після завершення перегляду.

Відеофайл передається тим самим механізмом, що й звичайні файли, тому
**прогрес передавання видно у вікні «Передавання файлів»** — для кожної
передачі показується смуга поступу з відсотками (0–100 %). Приймаються лише
відеоформати (`.mp4`, `.mkv`, `.avi`, `.webm`, `.mov`, `.wmv`, `.flv`,
`.mpg`, `.mpeg`, `.ogv`, `.m4v`, `.3gp`, `.ts` тощо). Обмеження розміру —
параметр `max_file_mb` (див. «Налаштування»).

Під час відтворення показується невелика панель **«Перегляд відео»** з
кнопкою **Зупинити й видалити файл** — вона зупиняє плеєр на всіх вибраних
комп'ютерах і видаляє файл. Панель **закривається автоматично**, щойно
перегляд завершиться на всіх вибраних комп'ютерах (або станеться помилка
відтворення/передавання). Надсилання нового відео автоматично зупиняє
попереднє.

На боці учня плеєр шукається серед типових (`mpv`, `vlc`, `mplayer`,
`ffplay`, `totem` тощо); якщо жодного не встановлено, файл відкривається
штатним обробником системи за замовчуванням (через `xdg-open`; на Windows —
через асоціацію файлів).

Сповіщення **«Відтворюється відео»** (а також повідомлення про відкриття
YouTube) показується учню лише на час запуску й **закривається автоматично**,
щойно почнеться відтворення — закривати його вручну не потрібно.

### Відео з YouTube

Кнопка **Відео з YouTube** приймає посилання й відкриває його у браузері за
замовчуванням на комп'ютерах учнів. Дозволено лише домени YouTube
(`youtube.com`, `youtu.be`, `music.youtube.com`, `youtube-nocookie.com`);
інші адреси відхиляються.

## Блокування інтернету та служба netguard

Для блокування виходу в інтернет у агента учня більше не використовуються права
адміністратора в його основному процесі. Замість цього введено окремий
привілейований клієнт **netguard** (`netguard.py`) з роллю `net`.

**Як це працює:**
- `netguard.py` підключається до вчителя **окремим TCP-з'єднанням** із роллю
  `net` і отримує команди блокування/розблокування інтернету (`MSG_NET`).
- На Linux блокування реалізовано через **iptables/ip6tables** (власний ланцюжок
  у `OUTPUT`): локальна мережа (RFC1918), link-local, multicast, broadcast та
  IP комп'ютера вчителя **завжди пропускаються**; решта трафіку блокується.
- На Windows використовується **Windows Defender Firewall** із правилом для
  `remoteip=Internet` — цей діапазон не включає локальну підмережу, тому LAN
  залишається доступним.
- Netguard надсилає поточний стан (`MSG_NET_STATE`) вчителю, який показує його
  на картках учнів (бейдж «Інтернет заблоковано» тощо).
- При втраті зв'язку з учителем одразу після блокування netguard **автоматично
  знімає блокування** як запобіжник. При чистій зупинці служби блокування також
  знімається.

**Запуск вручну:**
- Linux: `sudo python3 netguard.py`
- Windows: PowerShell від імені адміністратора → `python netguard.py`

**Автозапуск:**
- Налаштовується з меню `skkk_student_setup.py` — кнопкою **«Додати в
  Автозавантаження»** (і прибирається кнопкою **«Видалити з
  Автозавантаження»**).
- Linux: додає завдання `@reboot` у `crontab` root (лог `/var/log/netguard.log`),
  потрібні права адміністратора.
- Windows: створює заплановане завдання `ClassroomNetguard`
  (запуск при вході, найвищі права, від імені SYSTEM), потрібен запит UAC.

**Важливо:** блокування інтернету працює **лише** коли на комп'ютері учня
запущено `netguard` з правами адміністратора (root/Administrator). Основний
агент (`student_agent.py`) тепер **не виконує блокування** — він лише передає
екран і не потребує підвищених прав для цієї функції. Якщо netguard не
підключено, вчитель побачить попередження «Немає netguard — блокування не
застосовано».

## Якщо агент пише «Вчителя не знайдено»

Автовизначення використовує UDP-широкомовлення, яке часто блокує фаєрвол або
не пропускає мережа (звичайний `ping` цього не показує — це інший протокол).
Агент і сам надсилає підписаний запит, і перебирає адреси підмережі напряму,
тож пряме з'єднання працює навіть там, де широкомовлення заблоковане.

1. **Найшвидше рішення** — вказати IP учителя вручну (оминає автовизначення):
   ```bash
   python student_agent.py 192.168.1.10
   ```
2. **Кілька мережевих інтерфейсів на вчителі** (Ethernet + Wi-Fi + VMware/
   VirtualBox/Hyper-V) — широкомовлення може йти не тим інтерфейсом. Створіть
   поряд із `teacher.py` файл `classroom_config.json` із directed-broadcast
   адресою вашої підмережі (для `/24` це `x.y.z.255`):
   ```json
   { "broadcast_address": "192.168.1.255" }
   ```
3. **Фаєрвол** має пропускати вхідний **UDP 8766** на комп'ютері учня (щоб
   доходили оголошення/відповіді) і вхідний **TCP 8765** на комп'ютері
   вчителя. Обидва порти програма намагається відкрити автоматично.
4. **Різні підмережі / ізоляція клієнтів на Wi-Fi** — широкомовлення не
   перетинає межі підмережі; використовуйте пряму IP.
5. Переконайтеся, що токен скопійовано правильно (однаковий файл
   `classroom_token.txt` на вчителі та учнях).

## Якщо агент пише «Модуль tkinter недоступний»

Це означає, що в системі немає модуля `tkinter` (він не входить до частини
дистрибутивів за замовчуванням, зокрема antiX). Перевірити:
```bash
python3 -c "import tkinter, sys; print(sys.executable, tkinter.TkVersion)"
python3 -c "from PIL import ImageTk; print('ImageTk ok')"
```
Якщо перша команда дає помилку — встановіть пакет:
```bash
sudo apt update && sudo apt install python3-tk python3-pil.imagetk
```
Без `tkinter` агент усе одно передає екран учня, але:
- не показуватиме демонстрацію екрана вчителя;
- не підтримуватиме блокування комп'ютера та блокування введення.

Якщо ви використовуєте віртуальне середовище — `python3-tk` має бути
встановлено для тієї ж версії Python, що й саме середовище.

## Обмеження та безпека

- Прототип використовує звичайний TCP **без TLS**: зображення екрана, файли
  й токен передаються незашифрованими. Використовуйте лише в довіреній,
  ізольованій шкільній мережі. Для розгортання додайте TLS-сертифікати,
  облікові дані для кожного пристрою, журнали доступу та обмеження фаєрвола.
- Це не прихований агент: процес обміну видимий, і учнів слід повідомляти.
- Windows може запитати дозвіл фаєрвола — дозволяйте лише для
  приватної/шкільної мережі.
- Запуск файлів, що виконуються (`.exe`, `.bat` тощо), заблоковано за
  замовчуванням; вмикайте `allow_executable_files` лише за потреби й
  усвідомлено.
- У режимі перегляду відео учень приймає лише відеоформати; файл лежить у
  тимчасовій теці й видаляється після перегляду або команди зупинки.
- Для YouTube відкриваються лише дозволені домени — довільні посилання не
  передаються до браузера.
